# data/

The project's local data lake. **Large files are never committed to git.** Only these README files, `catalog/` and `manifests/` are tracked.

| Folder | Contents | Mutable? | Tracked in git? |
|---|---|---|---|
| `raw/` | Untouched downloads from official archives (PDS, USGS, HiRISE). Byte-for-byte as retrieved. | **No** (immutable) | No |
| `interim/` | Format-converted / clipped / metadata-extracted intermediates. Can be regenerated from `raw/`. | Yes (disposable) | No |
| `processed/` | Analysis-Ready Data (ARD): Cloud-Optimized GeoTIFFs aligned to the Jezero ARD grid, plus derived layers (slope, hazards, ...). Can be regenerated. | Yes (regenerable) | No |
| `sample/` | Small **clipped subsets of verified real products** for demos and integration tests. Each needs a catalog record. | Rarely | No (documented in catalog) |
| `catalog/` | One JSON record per dataset/layer: provenance, CRS, epistemic class, checksums. | Yes | **Yes** |
| `manifests/` | Download manifests: source URL as retrieved, retrieval date, file size, SHA-256. | Append-only | **Yes** |

Rules (see `AGENTS.md`):
- Nothing enters `raw/` unless it has a dataset dossier in `docs/data_sources.md`.
- Never edit files in `raw/`. Re-download instead.
- Never place fabricated, simulated or "example" data that imitates a NASA product anywhere in `data/`. Synthetic test surfaces belong in `backend/tests/` and must be generated by code.
- Set `MARSWALK_DATA_DIR` to move the data lake to an external drive.
